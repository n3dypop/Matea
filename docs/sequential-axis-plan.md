# 未達軸を一つずつ完了させる実行計画

2026-10-22。所有者の指示により同時に改善する評価軸は **1つ** とする。
元の48軸のうち検証器の性能1軸は資格確認まで完了済み。残りは47軸
（参照21、性能26）。完了済みの検証器を再度の改善対象にしない。

現在の対象は **`matea-style/lib` / reference（50）**。Help、Cursor、Spinner、
Progress、TextInputの装飾互換性が依存するため、共通の契約を先に実装する。
これらのウィジェットや他の性能軸を同時に昇格させない。

この軸の中も次の小項目を順に処理する。小項目の完了を軸の完了と数えない。

1. 色入力：文字列表現、明暗と能力別選択、明示的な色深度・アルファ、
   既定色と不正入力、参照元の色演算との差を固定fixtureと独立モデルで検証。
   現在の実装範囲はnative/Miri/3 OS CIの照合まで完了。精密/custom変換の残件は4で扱う。
2. 共通装飾の型と寸法：セルStyleの軽量性を維持してpadding、margin、
   border、min/max寸法、alignmentとinherit/unsetの責務を分離する。
3. 装飾した文字の構造化描画：wrap、clip、transform、hyperlink、空白の
   個別styleと背景、Unicode境界を参照元と独立セルモデルに結ぶ。
4. 全宣言の閉包：Lip GlossだけでなくRatatuiとx/ansiのstyle公開項目、
   feature/target、精密色とgradientを照合する。未対応項目は実装する。
5. 当該軸の最終確認：公開宣言→実装→正負試験の全対応、Rust API/DXの例、
   native全検証、必要なMiri、3 OS/MSRV CIを固定して採点する。

達成判定の前には未完行がないことを確認する。閾値75、元の評価単位、
公開機能範囲を変更しない。性能の未測定やadverseを参照互換性の試験で
解消したことにしない。失敗した試験と不採用案は保存し、同じ理由で進まない
場合は比較境界・仮説・実装方針を見直す。

この軸が完了してから依存するウィジェットの参照軸を順に選ぶ。続いて
runtimeの配送・取消、残る公開機能とnative条件、各性能軸を一つずつ閉じる。
各軸の原因・受入条件は[元の全件分析](unmet-axes-analysis.md)を保持する。
全軸高評価→横断最適化Stage B→F5報告→所有者の明示承認という順序は維持。
画像エンジン／codec／CUDAは開始しない。
