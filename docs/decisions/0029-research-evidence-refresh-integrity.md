# ADR 0029: Validate research inputs before publication and preserve reviews

Status: accepted for Foundation tooling.

The compiler-profile importer previously wrote early input files before validating later reports. A failed import could therefore alter published evidence while leaving the old index. The issue collector rebuilt open-issue records with pending/untriaged defaults, erasing earlier Matea review decisions on refresh. These are evidence-integrity defects found by source review.

Validate all compiler-profile inputs first, including pins, profile identities, all three success exit codes, unique item keys, and conflicting same-name files. Only after validation, stage canonical UTF-8 facts and atomically replace individual files, publishing the index last. This is not a filesystem-wide transaction: interrupted replacement and concurrent independent importers remain limitations. Invalid input must not modify any existing artifact.

Refresh issue metadata by repository and issue number while retaining reproduction, disposition and additional review evidence. Keep missing records in a separate prior-review list, labeled only as absent from the current open snapshot. Absence is not proof of closure. Reopened reports recover their earlier review. Flag changed upstream timestamps for further review. Validate pagination and repository identity, reject duplicate IDs, and finish every repository before replacing the published JSON. Network failure must not erase earlier research. Issue bodies remain outside the repository.

Tests cover malformed late profiles, duplicate/conflicting facts, canonical idempotent import, changed/disappeared/reopened issues, PR filtering, duplicate/foreign IDs, later network failure, and failed filesystem replacement. No real upstream metadata is refreshed by these regression fixtures. Load measurements and external compiler/network execution on each OS remain separate evidence.

The performance reporters now share a reader that rejects duplicate case IDs/JSON fields, empty inputs, nonfinite or nonpositive times, invalid iteration counts, and negative/nonfinite allocation counters. Historical Go allocation averages remain fractional; old absent return values remain absent. They are not silently converted into modern probe records. The main matched reporter generates and validates its complete result before copying incoming raw samples over published evidence. The existing historical data is still readable without rerunning or overwriting its measurements. A rejected input regression asserts byte-identical retention of published evidence.

Coverage reporting now canonicalizes paths while retaining each compiler instance and its own counters. A module included by both a production library and a custom benchmark must not be reported twice as separate physical sources, or silently reduced to the most favorable percentage. The quality gate rejects duplicate coverage paths and noninteger ordinal scores. A fixture retains both 0% and 100% instances of the same source. Import planning also reuses each already-validated parsed JSON value for canonical encoding, removing duplicate disk reads/parses without skipping validation.

Historical report CLIs now have a read-only `--check` mode, including a regression that it neither creates nor changes evidence. Validation resolves the native probe `.exe` suffix on Windows. The clock reporter no longer requires three hard-coded disposable macOS paths: callers may supply the available binaries explicitly, omitted verification stays null, and retained hashes are labeled unverified. The optional three-OS reference-path CI executes all five historical reporters in check mode, not as fresh performance measurements; it keeps full Git history to verify baseline source hashes.

The first expanded CI exposed a toolchain prerequisite: the pinned Lip Gloss `go.mod` requires Go 1.26.7, while ordinary parser-only CI intentionally uses Go 1.26.0. Pin the reference/probe job to Go 1.27.2, the version recorded by the native comparison, and retain 1.26.0 for the standalone stdlib auditor fixtures. A previous Windows CLI smoke also captured a 0 ns batch with only 20 operations. Increase that correctness-only CI batch to 20000 while retaining the strict positive-sample validator; shared-runner timings are still not performance evidence.

The new cross-OS Go trajectory wrapper initially imposed a generic 1e-12 comparison on springs, stricter than the existing `matea-motion/tests/reference.rs` spring contract (`abs(error) < 1e-6`). Linux/amd64 failed the new wrapper while the established Rust trajectories passed. Compare exact inputs and finite outputs with the unchanged existing spring/projectile criteria, reject malformed data, and record each OS's observed maximum errors. No Rust numerical test or quality threshold is changed. The Go fixture CLI also uses 20000 iterations to avoid zero-resolution Windows batches; strict positive sample validation remains in place.
CI correctness execution uses a distinct `probe-output` record kind under `MATEA_PROBE_OUTPUT_ONLY=1`. It executes each operation and emits its fixture output without timing/allocator fields. The strict performance reader rejects this format, and the output reader rejects measurement records. Raising every case's batch to resolve a coarse shared-runner clock made expensive Go screen cases exceed the wrapper's 120-second bound; that failed CI is retained. Output-only checking avoids both arbitrary timing floors and long timing loops. Normal native performance runs retain their original batches, 31 positive samples and allocation measurements; no threshold is relaxed.

Historical Viewport harness reconstruction explicitly applies its retained patch with per-command `core.autocrlf=false` and `core.eol=lf`. Windows checkout defaults changed reconstructed LF bytes to CRLF and broke the retained hash. A native regression emulates those defaults and fails before the fix. Preserve the original patch/hash and global Git configuration; normalize the reconstruction operation, not the measured evidence.
